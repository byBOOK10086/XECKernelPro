# 可信 keybox 证书指纹表（GPL-3.0，本项目整理，2026-10-08）
# ============================================================================
# 每行一个 sha256；比对对象是"规范化后的 PEM 证书体"：
#   把 keybox.xml 里 <Certificate format="pem"> 的内容去掉全部空白字符（含换行）
#   与 BEGIN/END 标记之后，对剩下的 base64 字符串本身取 sha256。
#   base64 体只由 DER 决定（换行位置不影响），所以无论镜像怎么重新排版都能命中。
# 解析实现见同目录 keybox.sh::kb_cert_hashes / kb_trust_level。
#
# 命中的意义：这个 keybox 的证书链里**包含**下面这些 Google Hardware Attestation
# 根/中间证书——也就是说它不是自签/伪造链（自签链在严格校验的检测方面前等于没有
# TEE）。注意这一层是"证书在不在链里"的指纹比对，不是密码学验证；链上的签名关系
# 由引擎与检测方在运行时验证。
#
# **2026-10-12 起，这份表不再是可信级别的判据**：级别只看**链末证书**是不是已知
# Google 证明根（见同目录 keybox_roots.txt，实现见 keybox.sh::kb_root_hashes /
# kb_trust_level）。原因是检测方（内置验机工具 wu.keyChain.test 的
# identifyRootCertificateType）只看链末证书的公钥，不看中间证书 —— 旧口径会因为
# 中间证书轮换把一份好箱子判成"级别 1"，也会把"链末是自签根/软件根"混进同一级别。
# 本表保留用于**日志取证**：kb_trust_hits() 报"链里有几张证书命中这张表"，
# 可用来交叉核对"链是不是被第三方重写过"（命中 0 项 + 链末非 Google 根 = 换过链）。
# 出厂那份 yurikey 盒子另做过一次私钥↔证书公钥一致性复核（结论：EC 与 RSA 两把
# 私钥的公钥部分都等于链首证书的 SPKI，且链首由中间证书签发、中间证书由根签发），
# 复核脚本与完整输出见交接文档 —— "指纹命中" + "私钥一致" 才等于可信密钥。
# 未命中不代表内容非法：仍然按"结构合法"接受（可信级别 1），只是日志会标注。
#
