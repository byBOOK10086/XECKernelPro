# XEC baseline coverage —— 由 builtin/tricky_store/service.sh 以**只增不删**的方式
# 并入 /data/adb/tricky_store/target.txt。
#
# 为什么需要它：引擎的拦截是**穷举白名单**。不在 target.txt 里的 UID 会被完全跳过
# （ConfigurationManager.kt 的 shouldSkipUid），原样拿到真实 TEE 证明——也就是
# "没列进来"等于"完全没生效"。而本模块历史上只在 target.txt 缺失时才播种，于是：
#   * 老版本留下的列表永远不会补上新工具；
#   * 管理器 / WebUI 改的是 /data/adb/.xudc_secure/target.txt，引擎读的是
#     /data/adb/tricky_store/target.txt，两边从未对账。
# 表现就是：刷了新版本，验机工具依旧报"未知认证根证书 / 无效的信任根状态"。
#
# 语义速查（引擎的解析规则）：
#   包名        自动：真实 TEE 可用就补丁，不可用就按 keybox 生成
#   包名!       强制按 keybox 生成新链
#   包名?       只补丁真实 TEE 链
#   [xxx.xml]   切换后续条目使用的 keybox（默认 keybox.xml）
#
# 只增不删：用户自己的条目、模式后缀与 [xxx.xml] 分组头都不会被改动或删除；
# 这里的条目若已存在（含带 !/? 后缀的写法）也不会重复追加。

# ── 2026-11-10：第三方**检测工具**改为运行时按 keybox 健康度决定 ─────────────
#
# 2026-11-08 的结论是"检测工具不注入"，理由是真机实测：链不可信时注入会递出
# "被篡改的 attestation key + 未知根证书"（OnePlus / Android 16：Tampered
# Attestation Key(26)、找到了 TEESimulator）。那份证据是对的，但结论过宽——
# 决定成败的是**链能不能自证**，而不是"注入"本身。
#
# 本轮读完 OhMyKeymint 1.2.6 的源码后确认：它让工具闭嘴靠的是把工具的 keystore
# 调用整体改投到一套能自证的实现；它自己的 FAQ 也写明 keybox 过期时工具看到的是
# "证书已过期"。所以我们把这条策略改成条件式，实现在 engineconf.sh 的
# `apply_detector_routing()`：
#
#   * 完整校验通过 + 根是 Google/Google-RKP + 叶子剩余 ≥ 7 天
#       -> 把工具以 `包名!` 写进 target.txt（`!` = 强制 GENERATE，用 keybox 现签
#          一条 Google 根的链；裸名是 AUTO，TEE 可用时会走 PATCH、拿到厂商根的真
#          实链，工具照样报"未知认证根证书"）
#   * 其余情况 -> 全部剥掉，让工具走真实 TEE
#       （宁可让工具看到"bootloader 已解锁"，也不递一张过期/厂商根的证书）
#
# 因此这一组**不出现在本 baseline 里**；用户也可以永久关闭：
#   touch /data/adb/.xudc_secure/verifier_forge_off
